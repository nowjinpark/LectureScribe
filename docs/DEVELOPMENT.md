# 개발 및 검증 가이드

## 요구 환경

- Apple Silicon Mac, macOS 26 이상
- Swift 6.2 이상, macOS 26 이상 SDK가 포함된 Xcode 또는 Command Line Tools
- 최초 패키지·음성 모델 다운로드를 위한 인터넷 연결과 약 630 MB 이상의 모델 저장 공간
- 생성 요약을 사용할 경우 지원되는 기기와 활성화된 Apple Intelligence

Swift Package Manager 프로젝트이며 공식 `argmax-oss-swift` 패키지의 **WhisperKit 1.1.0**을 사용합니다. 기본 작업은 녹음 저장과 기기 내 Whisper 전사이며 API 키와 Apple Intelligence를 요구하지 않습니다. 요약은 사용자가 따로 실행하는 선택 기능이고, 생성 모델을 사용할 수 없으면 핵심 문장 추출을 사용합니다.

음성 모델은 **`large-v3-v20240930_626MB`**로 고정합니다. 첫 전사에서 약 626.7 MB의 모델과 필요한 파일을 내려받아 `~/Library/Application Support/LectureScribe/SpeechModels`에 보관하고 다음 전사에서 재사용합니다. 모델·토크나이저 파일과 실행 중인 모델에 추가 저장 공간·메모리가 필요합니다. 최초 준비 시간은 네트워크와 Core ML 모델 로딩 상태에 따라 달라집니다. 녹음을 외부 API로 업로드하지 않습니다. [WhisperKit](https://github.com/argmaxinc/argmax-oss-swift), [모델 저장소](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-large-v3-v20240930_626MB)

## 빌드와 실행

저장소를 내려받은 뒤 프로젝트 루트에서 실행합니다.

```sh
swift --version
xcrun --sdk macosx --show-sdk-path
./scripts/build.sh
open "dist/강의노트.app"
```

빌드 스크립트는 Release 실행 파일과 아이콘을 `.app`으로 묶고 서명 및 서명 검증을 수행합니다. 기본값은 임시 서명(ad-hoc)이며 결과는 `dist/강의노트.app`입니다. Developer ID 배포에 필요한 공증 절차는 포함되어 있지 않습니다.

특정 SDK를 사용하려면 빌드·테스트 명령 앞에 `LECTURESCRIBE_SDK`를 지정합니다.

```sh
LECTURESCRIBE_SDK="$(xcrun --sdk macosx --show-sdk-path)" ./scripts/build.sh
LECTURESCRIBE_SDK="$(xcrun --sdk macosx --show-sdk-path)" ./scripts/test.sh
```

별도 지정이 없고 Command Line Tools의 26.5 SDK가 설치되어 있으면 스크립트는 이를 우선 사용합니다. SwiftUI 매크로 플러그인이 누락된 미리보기 SDK 환경을 피하기 위한 처리입니다. 인코더·통합 검증 스크립트는 `xcrun`의 현재 선택된 도구 체인을 사용합니다.

## 설치 파일 만들기

검증한 앱을 일반 macOS Installer 패키지로 묶습니다.

```sh
./scripts/build.sh
./scripts/package.sh
```

이미 검증한 `dist/강의노트.app`이 있으면 `package.sh`만 실행합니다. 패키징은 앱을 다시 빌드하거나 재서명하지 않습니다. 다른 검증본은 `./scripts/package.sh /path/to/강의노트.app`으로 지정할 수 있습니다.

출력은 `dist/LectureScribe-<버전>-arm64.pkg`와 SHA-256 파일입니다. `/Applications`에만 설치하고 macOS 최소 버전·arm64 요구사항을 적용합니다. 번들 이동을 허용하지 않고, 새 버전이 이미 있으면 낮은 버전 설치를 제한합니다. 설치 스크립트·권한 초기화·재부팅 동작은 포함하지 않습니다. 한글 앱 이름은 macOS BOM 생성에 맞춰 NFD로 정규화한 같은 표시 이름을 사용합니다.

패키지 생성 후 실제 payload를 확장해 `codesign --verify --deep --strict`와 원본 디렉터리 비교를 수행합니다. CI도 빌드 후 같은 패키징 검사를 실행합니다. 검사 중 현재 응용 프로그램 폴더를 덮어쓰지 않습니다.

유효한 **Developer ID Installer** 인증서가 있다면 `LECTURESCRIBE_INSTALLER_IDENTITY`로 패키지 서명 인증서를 지정할 수 있습니다. 앱 서명용 인증서와 별개이며, 이 변수만으로 앱에 Developer ID 서명이 추가되거나 공증이 완료되지는 않습니다. 현재 공개 파일은 서명·공증되지 않았습니다. 사용자 설치 과정과 보안 안내는 [설치 가이드](INSTALLATION.md)를 참고하세요.

## 녹음 권한과 개발 서명

**실행 중인 앱 불러오기** 또는 현재 녹음 대상을 누르면 선택 팝오버가 바로 열립니다. 목록에서 앱 이름 검색과 새로고침을 지원하며, 선택한 앱에 체크를 표시합니다. 앱 조회는 `NSWorkspace`를 사용하므로 화면·오디오 권한을 요청하지 않습니다. 앱 실행 후 첫 녹음 설정에서 Zoom이 실행 중이면 Zoom을 우선 선택합니다.

선택한 앱의 프로세스 ID와 번들 ID를 함께 보관합니다. 녹음 시작 전 목록을 다시 확인해 재시작된 같은 앱을 찾고, 대상이 없으면 시작을 막아 재선택을 안내합니다. 녹음 중 선택한 앱이 종료되면 받은 음성을 저장하고 종료 사실을 알립니다. 다른 앱이나 Mac 전체 소리로 자동 전환하지 않습니다.

`SCShareableContent`는 실제 녹음을 시작할 때 호출합니다. 최초 권한을 허용한 뒤에는 **⌘Q 또는 강의노트 종료로 완전히 종료하고 다시 실행**합니다. 창만 닫으면 메뉴 막대의 앱은 계속 실행됩니다. [Apple의 ScreenCaptureKit 예제](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)도 권한 허용 후 재실행을 안내합니다.

기본 ad-hoc 서명은 변경된 빌드마다 코드 식별이 달라질 수 있어 이전 녹음 권한이 유지되지 않을 수 있습니다. 설정에 허용으로 표시되더라도 앱을 업데이트한 뒤 녹음이 계속 실패한다면, 앱을 종료하고 **화면 및 시스템 오디오 녹음** 목록에서 **강의노트 항목만 −로 제거한 뒤 +로 현재 실행할 앱을 다시 추가**합니다. 응용 프로그램에 설치했다면 그 폴더의 앱을 선택하고 다시 실행합니다. 다른 앱의 권한을 초기화할 필요는 없습니다. [Apple DTS의 서명 설명](https://developer.apple.com/forums/thread/819406), [코드 서명 요구사항](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

키체인에 유효한 Apple Development 인증서와 개인 키가 있다면 빌드마다 동일한 서명을 사용하도록 지정할 수 있습니다. 아래 자리표시자를 자신의 인증서 이름으로 바꿉니다.

```sh
LECTURESCRIBE_SIGNING_IDENTITY="Apple Development: YOUR_NAME (YOUR_ID)" ./scripts/build.sh
```

이 변수는 기존 인증서를 선택하며 인증서를 생성하거나 녹음 권한을 자동으로 허용하지 않습니다. ad-hoc에서 인증서 서명으로 처음 전환할 때도 권한 재등록이 필요할 수 있습니다.

설치된 앱을 갱신할 때는 소스 수정과 테스트를 먼저 마치고 최종 빌드 한 번만 교체합니다. 녹음 중이 아닌지 확인한 뒤 앱을 완전히 종료하고, 기존 서명된 앱은 필요하면 되돌릴 수 있게 보관합니다. 최종 `.app`을 응용 프로그램 폴더에 복사한 뒤 그 위치의 앱을 실행·검증합니다. 여러 개발 복사본을 번갈아 실행하거나 빌드 때마다 권한을 초기화하지 않습니다. 임시 서명 업데이트의 권한 유지 문제를 해결하기 위해 코드 식별 검사를 약하게 만들거나 macOS의 권한 설정을 우회하지 않습니다.

## 자동 검증

```sh
./scripts/test.sh
./scripts/check-audio-encoder.sh
LECTURESCRIBE_ENCODER_SECONDS=3600 ./scripts/check-audio-encoder.sh
```

| 검증 | 확인하는 내용 |
| --- | --- |
| `CaptureApplicationTests` | 앱 재시작 후 동일 앱 찾기, 다른 앱에 재사용된 프로세스 ID 제외 |
| `TranscriptionServiceTests` | 읽을 수 없거나 빈 파일을 모델 준비 전에 거부 |
| `AudioSpeechRegionsTests` | 디지털 무음 제외와 작은 소리 보존, 원본 시간 위치와 파일 보존 |
| `WhisperAudioChunksTests` | 짧은 마지막 구간, 120초 읽기 경계, 전체 샘플 전달, 48 kHz 변환, 취소 |
| `SummaryServiceTests` | Unicode 보존 분할, 원문 근거 추출, 후반 주제 보존, 부정·일정 보존, 취소 |
| `WorkspaceStoreTests` | 파일 저장·재로드, 중단 복구, 경로 검증, 자막 시간·Unicode, 이전 요약 제거 |
| `check-audio-encoder.sh` | 합성 PCM → M4A, 길이와 초반·후반 소리·중간 무음 보존, 영상 트랙 없음, 빈 녹음 처리, 기존 파일 보호 |

단위 테스트는 실제 음성 인식 모델과 생성 모델의 품질을 평가하지 않습니다. 인코더 검증은 시스템 소리를 캡처하지 않고 합성 샘플을 실제 오디오 작성기에 전달합니다. 기본 길이는 2초이며 환경 변수로 1시간 분량도 검사할 수 있습니다. 인코더가 받아들이는 속도로 데이터를 공급하므로 실제 1시간 동안 녹음하거나 Zoom의 수신 음성을 검사하는 테스트가 아닙니다. macOS 오디오 서비스 접근이 제한된 실행 환경에서는 일반 터미널에서 실행해야 합니다.

## 음성부터 저장까지 통합 검증

합성 음성 또는 공개 가능한 검증용 음성과 실제로 발화한 원문을 준비합니다. 아래 첫 번째 인자를 실제 입력 파일 위치로 바꿉니다.

```sh
./scripts/verify-transcription.sh ./fixtures/korean-lecture.wav ./artifacts/transcription-smoke ko-KR
```

`fixtures/korean-lecture.wav`는 사용자가 준비하는 입력 경로 예시이며 저장소에 포함된 파일이 아닙니다. 전사 검증 스크립트는 실제 서비스를 호출하고 텍스트·시간 구간·`verification-report.json`을 저장합니다. 텍스트가 비어 있지 않은지, 시간 범위가 파일 안에 있는지, 구간 순서와 UTF-8 내보내기가 맞는지 확인하며 보고서의 `accuracyVerified`는 `false`로 기록합니다. 인식 정확도는 발화 원문과 별도로 비교해야 합니다.

선택 기능인 요약과 저장·재로드까지 확인하려면 60초보다 긴 한국어 파일로 다음 스크립트를 실행합니다.

```sh
./scripts/verify-pipeline.sh ./fixtures/korean-lecture.wav ./artifacts/pipeline-smoke
```

이 검사는 원본 사본·TXT·SRT·요약·메타데이터를 저장합니다. 보고서에는 사용한 `engine`, `accuracyVerified: false`, 구조 검사의 한계를 설명하는 `note`를 기록합니다. 구간이 유효한 파일 시간 안에 있고 순서가 맞는지 확인하며, 마지막 구간이 파일 끝에 닿아야 한다는 조건은 사용하지 않습니다. 마지막에 무음이 있으면 그 구간에 텍스트가 없어야 정상입니다.

앱의 기본 흐름에서는 요약을 자동 실행하지 않습니다. 핵심 문장 추출로 전환되어도 구조 검사에 통과할 수 있으므로 보고서의 `summaryMethod`와 `usedGenerativeAI`를 함께 확인합니다. 끝부분의 시간 정보나 파일 저장 성공만으로 모든 발화가 전사됐다고 판단하지 않습니다. 기존 음성 인식에서도 마지막 시간 정보가 있었지만 중간 문장이 누락된 사례가 확인됐습니다.

## 전사 모델 비교

2026-09-13에 같은 한국어 합성 음성 3개를 기존 Apple 기기 내 인식과 Whisper 전사 서비스로 처리하고 발화 원문과 대조했습니다. 문자 오류율(CER)은 Unicode NFC 정규화와 소문자 변환 후 문자·숫자만 남겨 계산합니다. 공백·구두점·기호는 제외하며, 삭제·치환·삽입 수를 정규화한 원문의 문자 수로 나눈 값입니다. 낮을수록 원문과 가깝습니다.

| 합성 음성 | 길이 | 기존 Apple 기기 내 인식 CER | WhisperKit CER |
| --- | --- | --- | --- |
| 데이터 주제 | 114.69초 | 16.48% | 0.32% |
| 물 주제 | 123.25초 | 12.59% | 0.14% |
| 네트워크 주제 | 131.84초 | 38.96% | 0.52% |

이 비교는 macOS의 Yuna 음성으로 만든 한국어 합성 자료에 한정됩니다. 실제 Zoom 수업, 자연스러운 강사의 발음, 잡음, 겹친 발화, 수 시간 녹음으로 일반화할 수 없습니다. 공백·구두점·대소문자를 제외하므로 해당 표기 품질은 이 수치에 포함하지 않습니다.

최종 서비스는 공개 VAD 분할기를 사용하는 앱의 어댑터로 최대 120초씩 읽고 최대 30초의 미확정 부분을 다음 읽기로 넘깁니다. 인식 입력은 구간당 최대 30초이며, 1초 이하의 마지막 부분도 전달합니다. 기본 SDK 로더의 짧은 꼬리 누락을 피하면서 원본에 인위적 무음을 붙이거나 PCM 임시 파일을 만들지 않습니다. 모델의 디코딩 종료 조건은 일반 구간에서 유지하고 매우 짧은 구간에 맞게 조정합니다.

Whisper가 긴 무음에서 발화하지 않은 문장을 추가하는 문제도 검사했습니다. 거의 디지털 0인 2초 이상의 무음만 전사 입력에서 제외하고 경계에 원본 오디오 0.25초를 남겼습니다. 추가 검사 결과는 다음과 같습니다.

| 입력 | 확인한 결과 |
| --- | --- |
| 약 15초의 짧은 한국어 합성 원본 | 원문의 4문장, 정규화 96문자 중 편집 거리 0 |
| 같은 발화에 앞뒤 무음이 있는 약 75초 파일 | 동일 4문장, 편집 거리 0, 무음의 추가 문장 없음 |
| 같은 발화를 앱별 캡처한 42.36초 M4A | 동일 4문장, 편집 거리 0, 원본 녹음의 시간 위치 유지 |
| Samantha 음성의 약 26초 영어 합성 파일 | 원문의 8문장, 정규화 379문자 중 편집 거리 0 |
| 0.264초 한국어 단독 발화 | ‘네’를 ‘네.’로, ‘셋’을 ‘3.’으로 인식 |
| 완전한 디지털 무음 | 모델 로딩 전 음성 없음으로 종료, 전사 텍스트 없음 |

위의 긴 한국어 음성 3개는 무음 검사로 잘리지 않았으며 같은 CER과 마지막 문장을 확인했습니다. 마지막 오디오 읽기·리샘플링 수정 후에는 48 kHz 캡처본과 네트워크 음성만 재검증해 각각 CER 0%와 0.52%가 유지됨을 확인했고, 나머지 결과는 해당 수정 직전 검사입니다. 무음 검사는 잡음·음악·작은 목소리를 분류하지 않으므로 모든 무음 오인식을 막지는 못합니다.

2026-09-13에 수행한 합성 음성·Zoom 스피커 테스트 검사와 저장된 보고서에서 다음 결과를 확인했습니다. 실제 수업 녹음 자료는 사용하지 않았습니다.

캡처·저장 검사는 인식 정확도 평가와 분리합니다. Zoom 스피커 테스트에는 발화나 원격 수업이 없으므로 앱의 디지털 소리가 저장된 사실만 확인합니다. 실제 Zoom 수업, 장시간 실시간 캡처·전사, 배터리 사용량, 여러 기기·OS 조합은 아직 검증 범위 밖입니다. 1시간 합성 인코더 검사 역시 수업 수신·캡처·전사의 전체 흐름을 대신하지 않습니다.

1.2.0 설치본에서는 모델 준비, 약 15.4초 예제의 재전사, 원문의 4문장과 시간 정보, TXT·SRT 자동 저장, 요약 자동 실행 없음, 완전 종료·재실행 후 기록 유지를 확인했습니다. 첫 녹음 설정의 Zoom 우선 선택도 확인했습니다. 앱 교체 직후에는 기존 macOS 권한이 적용되지 않았으나, 후속 검사에서 권한이 정상 적용되어 별도 초기화 없이 Zoom 녹음 시작과 디지털 소리 저장을 확인했습니다. 같은 설치본에서 기존 42.36초 QuickTime 캡처본도 다시 변환해 원문의 4문장, 원래 시간 정보와 TXT·SRT 저장을 확인했습니다. 실제 원격 수업의 녹음부터 전사까지 이어지는 검사는 아직 수행하지 않았습니다.

앱 목록 반복 조회, Zoom 검색·선택·재선택 표시, 검색 결과 없음 안내, Esc로 목록만 닫기가 권한 요청 없이 동작하는 것을 설치된 1.1.2에서 확인했습니다. 실제 녹음 시작 시의 권한 허용은 별도 단계입니다.

1.2.0의 기본 흐름은 **폴더 선택 → Zoom 선택 확인 → 소리 재생 중 녹음 → 종료 → 전사 → TXT·SRT → 재실행**입니다. 수동 확인에서는 녹음 대상의 이름과 파형, 저장한 음성의 앞·중간·끝 발화와 전사의 내용 일치, 내보내기 파일의 일치를 함께 확인합니다. 녹음 전 앱 재시작과 녹음 중 대상 앱 종료, 창을 닫았다 다시 여는 동작도 점검 대상입니다.

전사 결과에 생성 모델을 통한 재작성이나 특정 단어의 강제 치환을 적용하지 않습니다. 인식 오류를 숨기지 않고 저장된 음성과 시간 정보를 대조할 수 있게 합니다. 요약은 따로 실행하며, 생성된 내용이 원문에서 뒷받침되는지 검토해야 합니다.
